# Paralyn engineering instructions

The user adopted [Master Engineering Mandate v1.1](docs/master-mandate-v1.1.md). Read it and the current `docs/status.md`, `docs/architecture.md`, `docs/cuda-compatibility.md`, `ROADMAP.md`, and `docs/portfolio-ledger.json` before extending the system. Mandate version 1.1 is not software version 1.1; the current software remains 0.0.1.

- Continue this repository. Preserve existing working code, user changes, acceptance gates, and historical evidence. Do not restart or rewrite the compiler speculatively.
- All 17 frontend/input families and all three named interoperability clients in the ledger are required phased work. A checkpoint, a placeholder, or one extra frontend does not complete the portfolio. Keep framework adapters, operator providers, frontends, and execution backends distinct.
- Reproduce the qualified CUDA/Metal baseline and preserve Gate B while advancing through dependency-ready stages in `ROADMAP.md`; the native C/C++ byte-buffer API and Python bindings now exist; follow the exact next task in `docs/handoff.md` for remaining array/operator and backend work. Stage ordering does not make later obligations optional. Document evidenced blockers and continue independent work.
- Preserve ordinary supported host C++ semantics, exactly-once launch expression evaluation/order/conversions, unsigned CUDA indices, source diagnostics, exit status, allocation-token ownership, same-type alias groups, ordered execution, resource retention, and error propagation.
- Never fake output, special-case canonical inputs, suppress failures, silently change precision, claim unsupported compatibility, falsify device identity, or execute GPU kernels on a CPU fallback. Host code and explicit CPU test references are separate from kernel execution.
- Every advertised path requires actual input, compilation/import, real device execution, and independent verification. Record exact versions/hardware and positive/negative tests. Hardware absence is unavailable, not passing. Gate B and the documented benchmark protocol are required before tagging a qualified release.
- Keep `artifacts/gate-a/` and `artifacts/paralyn-gate-a/` unchanged. Future evidence must also preserve transformed host source. Only actual comparisons may print `Verification: PASS`.
- Keep CUDA-specific tokens outside future native buffer APIs. Do not force tensor graphs or mature compiler bridges through CUDA or the small scalar IR. Add abstractions only when an implemented consumer needs them.
- Use public documented interfaces and review licenses/provenance before dependencies or binary translation. PTX and SASS remain separate required tracks with separately established artifact rights, ABI subsets, tooling, and reference hardware. No proprietary implementation copying.
- Trusted local native code only until a stronger threat model is implemented. No unreviewed secret-bearing hardware CI, cloud spending, enrollment, or automatic remote execution. Publication, pushes, packages, and releases require separately applicable user authorization; adopting this mandate alone does not authorize them.
- Preserve command/import compatibility during deliberate naming transitions and separate renaming from functional changes. Paralyn is a working name, not a legally cleared brand.
- Update the ledger, matrix, numerics/execution contracts, actual status, and resumable handoff with evidence. Research/design/scaffolding remain incomplete work. Keep local changes/commits bounded and do not overwrite unrelated changes.
